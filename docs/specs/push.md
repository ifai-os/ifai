# 浏览器推送

## 目标

2026-11-02 站长要的：看到一篇新闻或一个 AI 工具时，在浏览器里点一下就推进采集流程，不用复制网址再去后台。推进去的和我们自己采到的走同一套判重和流程。

先接**线上网站**（生产或某个预览环境）。本地 Mac Studio 上的新闻流水线（飞书）还没有接收入口；插件的网站地址可以改，以后本地流水线照同一个接口收，就能直接换过去。

## 设计稿

没有画板：这是站长自己用的工具，插件界面照前台的红色和字体栈，跟着系统深色。

## 怎么用

- Chrome 插件，代码在仓库的 `extension/`（Manifest V3，纯 JavaScript，不用构建）。装法见 `extension/README.md`。
- 工具栏图标（或 Alt+Shift+I）弹出面板：页面标题和网站，两个按钮「推为新闻」「推为应用 / 工具」，猜得到的那个是红色。猜法：页面写了 `og:type=article`、发布时间或 JSON-LD 的 Article 类就是新闻；JSON-LD 是 SoftwareApplication / WebApplication，或者是网站首页、只有一层路径（`/pricing`）就是工具。猜错了点另一个。
- 右键菜单：在页面上或某个链接上「推到 IFAI：新闻」「推到 IFAI：应用 / 工具」。推右键的链接时只有网址（没有页面标题，取正文时用原文的标题补上）。结果显示在工具栏图标上（✓ 或 !，悬停看说明）。
- 设置页：网站地址、推送令牌；保存时浏览器会问是否允许访问这个网站（插件只访问设好的这一个）；保存后测试连接，并提示这个环境的 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED` 有没有打开。

## 接口

`POST /api/push`，JSON：`{ kind: "news" | "app", url, title?, summary?, publishedAt?, siteName?, name? }`。`GET /api/push` 只回答连得上没有、是谁、两个开关。

- 认证：`Authorization: Bearer $PUSH_TOKEN`（Vercel 环境变量，生产和预览各一个，和 `STORY_IMPORT_TOKEN` 分开），或者已登录的后台管理员。网站会员的令牌不行：推送是编辑的事。
- 代码：规则 `src/modules/push/rules.ts`，新闻 `news.ts`，应用 `apps.ts`，接口 `src/app/api/push/route.ts`。

**新闻**

- 网址照采集的规则清理（`src/modules/daily/url.ts`：小写域名、去掉跟踪参数和 `#`、去掉结尾的 `/`），页面的 canonical 在同一网站时用 canonical。网站首页不收。
- 判重和采集一样按网址：`raw_items` 里已有（不管哪个信源采到的、在流程哪一步），就不再加，回复里写它现在怎样：等判断、没过线（附原因）、归入了哪条新闻、那条新闻的状态，插件给出后台链接。
- 新的一条记进 `raw_items`：归在**同一网站的信源**下（信源的抓取地址或首页在这个网站上，优先启用的那个），这样信源等级和名称照旧；没有就新建一个**停用**的信源，名称用页面的 `og:site_name`（没有就用域名），等级 T1，从不抓取。不共用一个「浏览器推送」信源，因为信源名称就是新闻来源列表里显示的发布方。`external_id` 记 `push`。
- 页面写了发布时间、而且超过 48 小时：和采集一样只存档，不进日报，插件里说明。
- 然后发 `daily/item.fetch-content`：取正文 → 判断（相关性、两次评分、结构化、和已有事件归并）→ 写作 → 后台待审核，和采集到的一模一样，也照样受 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED` 和预算管。Inngest 一时排不上，判断的定时清扫一小时内会补上取正文。
- 评分照样要过信源等级的线；站长推的不开绿灯（要的话以后再加）。

**应用 / 工具**

- 取网站的首页（`https://域名`），照「批量添加应用」（`src/modules/apps/profile/import.ts`）按域名判重：已有这个域名的应用（上架、草稿、下架都算）就回复是哪个，不改它。
- 新的建成草稿应用，名称用页面的应用名（JSON-LD、`og:site_name`、`application-name`），没有就取标题的第一段（「Cursor - The AI Code Editor」→ Cursor），再没有就用域名，等资料草稿起名。然后排资料草稿，和批量添加一样；排不上时定时清扫每 20 分钟补。

## 不做

- 书签小工具：令牌没地方安全地放，跨站请求还要开 CORS。只做插件。
- 推送时附备注、指定分类：流程自己判断；要改在后台审核时改。
- 推进本地 Mac Studio 流水线：等那边有接收入口。

## 验收

- [ ] 在预览环境填好 `PUSH_TOKEN`，插件设置页保存后显示「连上了」
- [ ] 打开一篇当天的新闻，点「推为新闻」：后台「日报 → 信源」里出现（或复用）这个网站的信源；开着两个开关时，过一会儿后台待审核里有这条新闻
- [ ] 再推一次同一篇（网址带 `?utm_source=`）：提示「已经有了」，没有多一条
- [ ] 推一个已有应用网站的任意页面：提示「已有这个应用」；推一个新工具：后台应用里多一个草稿，资料草稿在生成
