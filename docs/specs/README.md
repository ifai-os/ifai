# 模块规格

每个模块开工前写一页规格，放在这个目录（`daily.md`、`apps.md`、`resources.md` …），再按规格实现。规格写清楚「做什么、做到什么程度算完」，不写实现细节。

| 规格 | 状态 |
|---|---|
| [foundation.md](./foundation.md) — 第 1–2 周地基 | 已实现 |
| [daily.md](./daily.md) — 日报 | 已确认，待实现 |
| apps.md — 应用 | 待写 |
| [resources.md](./resources.md) — 资源（Agent Skills） | 草稿，待确认 |

## 模板

```markdown
# <模块名>

## 目标
一两句话：这个模块给用户解决什么问题，上线时做到什么程度。

## 设计稿
画布上的画板名（桌面、手机、空状态），以及和画板不一致的地方。

## 数据
集合 / 表、关键字段、哪些字段 localized、谁能读写。

## 页面与路由
/[locale]/... 每个页面显示什么、从哪里取数据、缓存与更新频率。

## 后台
编辑在 Payload 里怎么录入、审核、发布。

## 定时任务与 AI
用到的任务、模型用途（经 src/lib/ai）、失败时怎么降级。

## 多语言
哪些内容需要翻译、由谁翻译、繁体如何生成。

## 不做
这一期明确不做的事。

## 验收标准
- [ ] 可以逐条验证的结果（含五种语言、手机宽度、空状态和加载状态）
```
