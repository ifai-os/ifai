# 排行（模型盲测）

状态：已确认（2026-10-25，站长合并 #66 时对「已定的规则」里标「按推荐」的几条没有异议，以后可以再改）；第 1 步已合并（PR #66），第 2 步（图像生成赛道）已实现；页面在第三期前不开放

## 目标

回答读者最常问的「哪个模型更好用」：同一道题交给两个匿名模型，读者看完两份回答再投票，排名来自这些两两对比，而不是厂商自测。和「应用」的热度榜分开：应用榜看的是产品有多少人在用，这里看的是模型回答得好不好。

第三期要做到：按赛道（文本、编程……）的排行页（前 10、性价比、完整榜单、走势、按厂商）、盲测投票页、站长维护的参赛模型和题库、每周一更新的排行快照。

## 已定的规则

1. **排行就是自建盲测**（按推荐）。依据是画布「IFAI 模型排行」画板和 AGENTS.md 的分期表。需求文档 v0.4 的 R06（按任务的编辑推荐榜，首批 TTS、图像生成、聊天应用）是另一种东西，应用规格里已经说过「以后单独立项」；外部榜单（Artificial Analysis、Arena 等）没有书面授权，不导入任何分数（技术方案第 5 节）。
2. **题库盲测**（按推荐）：题目由站长在后台写，每道题每个参赛模型只回答一次，回答提前生成好存起来；读者投票时看的是存好的回答，投票本身不调用模型。这样花费一次性、可控，回答可以先在后台看过，也不会有人借投票页让模型生成任意内容。读者自己出题放到以后（见「不做」）。
3. **第一批赛道：文本、编程**，迁移里带好，五种语言，后台可以改名、加赛道、调顺序。画板上的图像生成在第 2 步加上（见「图像生成赛道」）；视频生成、搜索、网页开发、综合 Agent 需要别的生成方式，暂不排期。
4. **参赛模型由站长在后台加**：显示名、厂商、OpenRouter 模型 ID、开放权重还是闭源、许可名称和链接、厂商所在地区、参加哪些赛道。状态三种：**备赛**（只生成回答，不进盲测）、**参赛**、**退役**（不再出题，也不在新的排行里，票照样留着）。第一批模型和题库由站长定（status.md「以后再定」）。
5. **每道题写一种语言**：英语、简体中文、日语、韩语之一，回答用同一种语言。繁体中文页面出简体题，题目和回答都用 OpenCC 转成繁体显示（AGENTS.md 第 4 条）。页面语言没有题时出英语题。一道题有了回答以后不能再改题目，要改就新建一道、把旧的停用，免得回答对不上题。
6. **所有模型拿到同一段说明**：用题目的语言直接回答，不提自己的名字、模型和公司，用纯文字、代码放进代码块，回答最多 4000 个 token。回答里出现了自己的模型名或厂商名、或者写到上限被截断的，不进盲测（后台标出来，可以重新生成）。
7. **投票要登录**（按推荐）。选项四个：A 更好、B 更好、差不多、都不好。两边的顺序随机，投完才显示两边各是哪个模型。每人每个上海自然日最多 200 票；打开题目不到 4 秒就投的票照收、不计分（来不及读完）；最近投过的 50 道题不会再出给同一个人。
8. **分数**：Bradley–Terry 模型，用全部计分的票拟合；「差不多」和「都不好」各算半场。平均水平是 1000 分，差 100 分大约是 64% 对 36% 的胜率。95% 区间用 bootstrap（按票重抽 100 次）算，页面写成「±」。**每周一 06:00（上海时间）重算一次，存成这一周的快照**，页面只读快照；站长可以「现在重算」，同一周重算会替换这一周的快照。
9. **暂定**：计分的票不足 300 的模型标「暂定」，不排名次、不进前 10 和性价比图，在完整榜单里排在有名次的模型后面（画板写 1,000 票，起步流量小，按推荐先用 300，`src/modules/rankings/rules.ts` 的常量）。不暂定的按分数从高到低排 1、2、3……，分数相同按票数。
10. **「开放权重 / 闭源」**（按推荐），不写「开源」：需求文档要求开源筛选区分开放权重、开源代码和商用条件，不能用「开源」代替许可核验。表格里只显示这两种，模型的许可名称和链接站长填了才显示，没填不猜。
11. **地区按厂商所在地**：美国、中国、欧洲、其他。筛选只出现榜单上实际有的地区。
12. **成本 / 任务** = 这个模型在这个赛道所有回答的平均费用（OpenRouter 报的美元价）。没有费用数据的模型显示「—」，不进性价比图。
13. **生成回答的花费**每天最多 `ARENA_DAILY_BUDGET_USD`（默认 2 美元，上海自然日），也算在全站每日预算（`AI_DAILY_BUDGET_USD`）里；用完了第二天接着生成，不挤占日报和应用的调用。
14. **数字都是真的**：页头的「次对比投票」是全部计分的票数。

## 页面与路由

导航上的「排行」在 `NEXT_PUBLIC_SITE_PHASE` = 3 时出现；不到第三期时页面和接口都是 404。

**`/[locale]/rankings`、`/[locale]/rankings/[arena]`** 排行页。`/rankings` 是排第一的赛道，其他赛道各有自己的地址（`/rankings/<第一个赛道>` 跳回 `/rankings`）。快照和页头数字缓存一小时，快照算好、后台改赛道或模型时刷新。

- 页头：「模型排行 · 每周一更新」、标题、一句说明、全部计分的票数、「参与盲测投票」（去这个赛道的盲测）。右边「新上榜」（规则见上表）。
- 赛道标签：已上线的赛道，链接到各自的地址。下面一行写这个赛道的一句话介绍和快照日期（上海时间的日期，和每周一 06:00 对齐：「10 月 20 日更新」）。
- 「<赛道> · 前 10」：横条，长短按分数，第一名黑底，前三名次红色。
- 「性价比」：横轴成本 / 任务（对数），纵轴分数；虚线连起「没有更便宜又更强的」模型（帕累托前沿），前沿上最后三个写名字；下面列「最划算的选择」三个。有成本的模型少于 3 个时不显示这一块。
- 「完整榜单」：名次（前三红色）、模型（厂商首字方块、名称、厂商）、分数、区间（±）、票数、许可（开放权重 / 闭源）、成本 / 任务。上方「全部许可 / 开放权重 / 闭源」「全部地区 / 美国 / 中国 / …」筛选，记在地址里（`?weights=open&region=cn`），带筛选的页面 `noindex, follow`。下面一行写算法和暂定的说明。
- 「分数走势 · 近 12 周」：每周闭源第一和开放权重第一的分数两条线，下面一句「两者的差距从 X 分变成 Y 分」（前后一样时写「保持在 X 分」）。快照不到两周时不显示。
- 「按厂商」：前 30 名里各厂商的模型数，前 5 个厂商。
- 空状态：还没有快照时显示页头和「第一份排行会在投票够了以后的周一出来」，按钮「参与盲测投票」。
- 不带筛选的排行页进站点地图的 `pages` 段（第三期起），`lastmod` 是最新快照算好的时间；带筛选的页面和投票页不进。

**`/[locale]/rankings/vote`** 盲测投票页（`?arena=<slug>` 选赛道，默认第一个）。`noindex, follow`。

- 页头「盲测投票」、一句说明、赛道标签（`?arena=`）。
- 题目卡片：题目原文（带题目语言的 `lang`），「换一题」。
- 两份回答：桌面左右两栏，手机上下排，标「模型 A」「模型 B」。回答按纯文字显示，代码块用等宽字体、可以横向滚动；模型写的任何标记都当文字显示，不执行。
- 四个按钮：A 更好、B 更好、差不多、都不好。投完两边标出模型名和厂商，选中的一边加框；不计分时写「这一票投得太快，不计入排名」；按钮换成「下一题」。
- 没登录时照样出题，点投票先弹登录对话框，登录完回到这一页，出一道新题。超过每天 200 票时写「今天投得够多了，明天再来」。这个赛道还没有能用的题时显示空状态。加载慢时是骨架，失败可以重试。
- 接口：`POST /api/rankings/battles { arena, locale }` 出一道题：返回题目、两份回答（不带模型）、对局 id（没登录时没有 id，也不存）；`POST /api/rankings/battles/<id>/vote { outcome }` 投票，返回两边的模型和是否计分。都只接受本站页面发来的请求（不然 403），投票要登录（401），对局不是自己的或不存在 404，已投过 409，出题超过 2 小时 410，超过每天的票数 429。

## 后台

- 左侧「排行」一组：赛道、参赛模型、题库、回答。
- 赛道列表上方：每个赛道最近一次快照（哪一周、什么时候算的、用了多少票、几个模型）和「现在重算」。
- 参赛模型编辑页的「回答」面板：每个赛道完成 / 等待 / 失败 / 不进盲测的回答数和花费，「现在生成」（把缺的回答排进生成任务）、「重试失败的」。模型改成「参赛」以后才进盲测。
- 题库：按赛道、语言、状态筛选。新建或启用一道题后，参赛和备赛的模型自动排队生成回答。
- 回答：只读（题、模型、回答、费用、截断、提到自己），站长只能「隐藏」：隐藏后不再出现在盲测里，已经投的票照算。
- 后台的保存和按钮都记进「操作记录」（`withAdminLog`）。

## 定时任务与 AI

- **生成回答**（`rankings-answers`）：每 30 分钟一次，后台保存模型或题目、按「现在生成」时也会跑。给缺回答的（题, 模型）建「等待」行，每次最多处理 30 条，一条一个步骤。用途 `arena`：这是唯一不在 `purposes.ts` 里定模型的用途，模型 ID 来自参赛模型名单（`ai.contest`），照样写回执、受总开关和每日预算管。`MODEL_CALLS_ENABLED` 关着、全站预算或 `ARENA_DAILY_BUDGET_USD` 用完时停下，下次接着。一条回答失败三次标「失败」，等站长「重试失败的」。
- **每周快照**（`rankings-snapshot`）：每周一 06:00（上海时间），或后台「现在重算」。先删两天前没投的对局，再给每个已上线的赛道算分（规则 8、9）、存快照、刷新排行页。还没有一个模型够 300 票的赛道不存快照，排行页保持空状态。
- 页面和接口不调用模型（AGENTS.md 第 8 条）。

## 图像生成赛道（第 2 步）

画板上的「图像生成」：题目是一段画面描述，两个模型各出一张图，读者看图投票。

- **赛道分两种**：文字、图像（赛道的「种类」），有了题目以后不能改。迁移加一个「图像生成」赛道（`image`），状态「准备中」：站长加好能出图的模型和题目、回答生成齐了，再改成「已上线」。
- **参赛模型**：OpenRouter 上输出有图片的模型（模型页的 output modalities 写着 image），和文字模型一样在后台加，赛道选「图像生成」。能不能出图由站长看模型页，加错了的回答会失败。
- **生成**：还是 `rankings-answers` 任务。图像赛道的题走 `ai.contestImage`：OpenRouter 的对话接口加 `modalities: ['image', 'text']`，每份回答只要第一张图，模型附带的文字不存。所有模型拿到同一句说明：按描述画一张图，图上不写签名、水印、模型名或公司名。图一拿到就存进「回答的图」（`arena-images`，线上在 R2），回执记下图的 id：之后哪一步失败，重试都不会再为这张图付一次钱。费用照样记回执，算进 `ARENA_DAILY_BUDGET_USD` 和全站预算。没出图的和空回答一样算失败，等「重新生成失败和不能用的」；存图失败的（比如 R2 连不上，或者模型给的不是 PNG / JPEG / WebP）和接口出错一样，下一次重试，三次以后等站长。
- **为什么不放进媒体文件**：媒体文件的记录谁都能列出来，记录的先后和时间会暴露哪几张图出自同一个模型（一个模型的图往往一起生成），投完一票知道一张，就能猜出一批。所以图单独放：文件谁有地址都能打开（投票页要显示），记录只有站长能看；文件名随机，不带模型、题目和顺序。
- **不进盲测**：没有图的、被隐藏的、图被站长删掉的（删掉的算「不能用」，可以重新生成）。图上的字识别不了，所以不查「提到自己」：站长在后台「回答」里看图，有签名、水印或者不该给读者看的就隐藏。
- **投票页**：两张图左右排（手机上下排），按原比例显示，最高 600px，点图在新标签页打开原图；替代文字是「模型 A 的图」「模型 B 的图」。题目、四个按钮、揭晓、计分和每天的上限都和文字赛道一样。
- **排行页**：和文字赛道一样，「成本 / 任务」是每张图的平均费用。

## 多语言

- 界面文案五种语言（`messages/`），繁体由 `pnpm i18n:hant` 生成。
- 赛道名称和介绍、厂商名由站长在后台写英、简、日、韩，繁体在后台保存时由简体转换；模型显示名不翻译。
- 题目和回答保留原文语言（规则 5），外层带它的 `lang`。

## 导出与删除账号

- 删除账号时对局的会员 id 置空（见「数据」）。
- **上线前**（把 `NEXT_PUBLIC_SITE_PHASE` 改成 3 之前）要补，现在不改，免得和账号、圈子两边正在改的同几个文件冲突，也免得第一期的页面写着还没有的东西：「下载我的数据」（`src/lib/auth/export-member.ts`）加上 `arenaVotes`：投过的票（赛道、题目、两边的模型、结果、是否计分、时间）；隐私政策「我们收集什么」「保留多久」加上盲测投票和「删除账号后票留下但不再关联你」，改生效日期；账号页「删除账号」的说明加上这一句。

## 不做

- 读者自己出题、多轮对话、上传文件（要实时调用模型、按人限额和内容审核，先看题库模式的投票量）。
- 导入外部榜单的分数（规则 1）。
- 按语言、按题目类型分榜，长度和格式的「风格控制」：上线后票多了再做（实现顺序第 3 步）。
- 模型详情页（各赛道分数、历史、回答示例、哪些应用在用它），等需求文档的「产品 / 模型目录」一起做。
- 读者评论、举报回答（回答由站长看过，有问题直接隐藏）。

## 实现顺序

1. **文字赛道的题库盲测和每周排行**：四个集合和两个首批赛道、生成回答任务、盲测投票页和接口、Bradley–Terry 快照、排行页（前 10、性价比、完整榜单和筛选、走势、按厂商、新上榜）、后台的面板和按钮。
2. **图像生成赛道**（见上面一节）：调用能出图的模型、存进「回答的图」（R2）、投票页按图片显示。
3. **按语言分榜和风格控制**，出题时偏向票少的模型：上线后票多了再做，现在的票不够分。
4. **上线前的文字**：导出、隐私政策和账号页（见「导出与删除账号」），首页加排行入口。

## 测试

- 单元测试：`tests/unit/rankings/`（规则、打分、两张图、生成回答和出图），`tests/unit/ai.test.ts`（`ai.contest`、`ai.contestImage`）。
- 示例数据：`pnpm payload run scripts/seed-rankings.ts` 往本机数据库加 13 个虚构模型（OpenRouter ID 以 `sample/` 开头，其中 4 个画图）、14 道题和回答（图像赛道的 16 张图是脚本现画的，四种比例）、4 周的票和最近 3 周的快照，三个赛道都改成已上线；其中一个模型最后一周才进来（新上榜），一个票不够（暂定）。可以重复跑。
