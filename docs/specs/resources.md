# 资源（Agent Skills）

状态：已确认（2026-10-22）

## 目标

收录能装进 AI 助手里用的 Agent Skills（一个目录：`SKILL.md` 加脚本和参考资料）。每个 Skill 有一个稳定的主页和若干不可改的版本；每个版本都经过静态安全检测，写明适配哪些宿主、需要什么依赖和权限；用户选好自己的宿主，复制一句话或下载 Zip 就能装。站内只展示和分发，不运行任何 Skill。

第一期要做到：你从 GitHub 导入并审核、列表与详情（桌面、手机）、版本与固定链接、静态安全检测、安装指令与安装统计、收藏、投稿表单、首页「新上架 Skills」接真实数据。

## 已定的规则

1. **第一期的资源只有 Agent Skills**（AGENTS.md 的分期表）。一个 Skill 就是一个符合 Agent Skills 规范的目录：`SKILL.md`（frontmatter 里有 `name`、`description`）加可选的 `scripts/`、`references/`、`assets/`。
2. **版本不可改**（需求文档 v0.4 的 R19）。版本发布后，文件、整包指纹、依赖和权限声明都不能再改，要改就发新版本。显示名、介绍、分类、标签可以改，改动留记录。固定链接永远指向那个版本；撤回的版本显示状态和原因，不自动跳到新版本。
3. **站内不执行任何 Skill。** 只做静态检测，不提供在线运行、自动安装。安装由用户在自己的宿主里完成。「安全检测通过」只说明静态检测的结果，详情页固定写一句：这不代表 IFAI 为它的功能或安全背书。
4. **Skill 的内容是数据，不是指令**（AGENTS.md 第 9 条）。SKILL.md、脚本、README 送进模型时只作为材料；前台把它们当文本渲染，不执行其中的 HTML 和脚本；外链加 `rel="nofollow noopener"`。
5. **两个徽章分开。** 「安全检测通过」是自动检测的结果，每个版本单独算；「IFAI 认证」是你亲自在至少一个宿主里装好、跑通 SKILL.md 描述的任务之后手动勾的，整个 Skill 一个。
6. **显示名和说明按语言本地化，内容不翻译。** slug、SKILL.md 正文、文件、安装路径只有原文。网址用英文 slug，五种语言共用，和日报一样。
7. **安装只有两种方式**：复制一句安装指令（自然语言，让用户的 AI 助手自己去读站上这个 Skill 的 `install.md` 并照做），或者下载 Zip 自己放进宿主的 Skills 目录。两种都算一次安装。
8. **第一期只显示 Skills。** 画板子导航里的 MCP 服务、提示词、模型、数据集不建页面和表；路由用 `/resources/skills/…`，给以后的 `/resources/prompts/…` 留位置。
9. **第一期不做评分和评价，只做收藏。** 卡片上用安装数、更新时间和检测徽章代替星级；评价放到第二期和圈子一起做。
10. **没有评测报告。** 详情页用「安全检测」页签展示逐项检测结果；认证的 Skill 在概述里有一段你写的「试用笔记」。
11. **宿主显示 6 个**：Claude Code、Codex、OpenClaw、Hermes、Pi、WorkBuddy。安装指令是自然语言，对哪个宿主都成立；兼容状态第一批只由你在 Claude Code 和 Codex 上验证，其余显示「未测试」。上线前要 6 个官方授权 logo（status.md 待办）。
12. **用户投稿只做轻量表单**：登录后填 GitHub 仓库地址、一句话说明、联系邮箱，进后台队列，由你导入和审核，结果邮件通知。不做作者自助上传 Zip、作者后台和「我的提交」页。
13. **第一批收录**从公开仓库挑 20–30 个（比如 `anthropics/skills` 和其他 MIT / Apache 许可的仓库），加上 IFAI 自己写的几个。只收有明确开源许可的，没有许可的要作者书面同意。清单在导入时定，定了写进这一条下面。
14. **安装数口径**：复制安装指令、下载 Zip、宿主拉取 `install.md` 各算一次；同一访客（IP 加浏览器指纹的加盐哈希，不存原始 IP）对同一 Skill 一天只算一次。「本周飙升」= 近 7 天安装数比前 7 天的增幅，至少 20 次才上榜。

第 8–14 条是 2026-10-22 从 7 个待定项按推荐确定的。

## 页面与路由

**`/[locale]/resources`** 列表页，第一期就是 Skills 列表。

- 顶部：标题、一句介绍、收录数和本周新增（真实数字，不凑数）、「发布 Skill」按钮。
- 本周精选：你在后台勾的那一条；没勾时取最近认证的一条。
- 三步用上 Skill：静态文案，指向使用指南。
- 本周飙升：前 3 条，不够 3 条就不显示这一块。
- 分类（带数量）、排序（综合 / 近期飙升 / 安装数 / 最近上新）、筛选（无需 API Key、仅看认证）、搜索（显示名、介绍、标签；数据库模糊查询，第一期不接 Meilisearch）、列表 / 网格切换（记在浏览器里）。分类、排序、筛选、搜索词、标签、作者都在 URL 查询参数里，刷新和分享不丢。
- 「综合」排序 = 认证优先，再按近 7 天安装数，再按更新时间。
- 每条：logo 或首字母占位、显示名、分类、「需 API Key」、一句话介绍、安装数、作者、更新时间、检测徽章（通过 / 检测中 / 暂不可安装），「安装」按钮进详情页的安装面板。
- 右栏：安装榜前 5（「完整榜单」= 按安装数排序的列表）、热门标签（= 按标签筛选）、投稿入口。
- 空状态按「搜索无结果」画板：保留搜索词，给热门标签。

**`/[locale]/resources/skills/[slug]`** 详情页，显示当前版本。

- 头部：面包屑（资源 / Skills / 分类 / 名字）、显示名、徽章（IFAI 认证、安全检测通过）、slug 和版本号、介绍、安装数、更新时间、API Key、标签、作者（点作者 = 按作者筛选的列表）、收藏（收藏的 Skill 出现在应用规格定义的「我的收藏」页 `/[locale]/me/saves`）。
- 页签：**概述**（它能做什么、使用示例、工作流程、注意事项、试用笔记、SKILL.md 原文可展开）、**文件**（目录树和大小，点文件名看转义后的原文）、**版本记录**（每个版本的日期、更新说明、状态，点进固定版本页）、**安全检测**（逐项结论、检测时间、外联域名清单、固定的免责说明）。
- 右栏安装面板：选宿主（6 个，每个带兼容状态）→ 安装指令随宿主变化 → 「复制安装指令」「下载 Zip」。下面是信息（版本、更新时间、许可、运行依赖、API Key、大小、来源仓库）、安全（整包 sha256、检测时间、「如何验证」指向使用指南）、相关 Skill（同分类按安装数取 6 条，「换一换」在这 6 条里轮换）。
- 检测中或未通过的版本：安装面板显示「检测中」或「这个版本暂不可安装」，按钮不可点，旧的通过版本继续可装。
- 已下架的 Skill：主页保留，显示下架原因（作者要求 / 违规），不显示安装面板，不是 404。

**`/[locale]/resources/skills/[slug]/v/[version]`** 固定版本页：内容同详情页，顶部提示「这是 vX，当前版本是 vY」；已撤回的显示原因，安装面板禁用。页面 `noindex`，只有主页进搜索引擎。

**`/[locale]/resources/guide`** 使用指南：三步说明、每个宿主的 Skills 目录位置和启用方法、怎么核对 sha256。**`/[locale]/resources/submit`** 发布指南加投稿表单（要登录；成功后显示编号，告知审核时间和通知方式）。

**语言无关的接口**（在 `/api/skills/` 下，不受语言前缀影响）：

- `GET /api/skills/[slug]/install.md`（可带 `?v=`）：纯文本，写明 Skill 名、版本、Zip 地址、sha256、每个宿主的目录位置和步骤。安装指令就是「请读取这个地址并按步骤把 Skill 装到 ＜宿主＞」。
- `GET /api/skills/[slug]/[version].zip`：核对状态后 302 到 R2 的短效地址，并记一次安装。

页面静态生成，发布、撤回、下架时按需刷新缓存；安装数和榜单每小时更新一次。首页的「新上架 Skill」读本周精选，「新上架 Skills」读最近发布的 4 条，替换 `src/modules/home/demo-data.ts` 里的演示数据。

**第 4 步的做法**（和上面不同、或上面没写的地方）：

- 列表不查数据库：已发布的 Skill 整体缓存一份（标签 `skills`），筛选、搜索、排序在内存里做（`src/modules/resources/public/order.ts`）。第一期几百条足够；条目多了再换数据库查询或 Meilisearch。搜索也查 slug。
- 列表每条的检测徽章说的是能安装的那个版本（「安全检测通过」或「已人工复核」）。更新的版本还在检测或没通过时，只在详情页安装面板里提示，列表不显示「检测中」，免得能装的 Skill 看起来装不了。
- 「发布 Skill」按钮、本周飙升、右栏安装榜和投稿入口、收藏，以及「三步用上 Skill」和指纹「如何验证」指向使用指南的链接，等第 5 步的页面和统计汇总做好再加。
- 下载：`/api/skills/[slug]/[version].zip` 核对后 302 到 Payload 的文件地址，配了 R2 时由它再 302 到 5 分钟有效的签名地址（两跳）。访问控制只写在一处：撤回的版本、下架的 Skill，连文件地址本身也不给。这个地址由 `next.config.ts` 的 rewrite（只匹配「数字开头、`.zip` 结尾」）交给 `src/app/api/skill-zips/`：`/api/skills/` 下两段的地址还有 Payload 自己的（如 `/api/skills/versions/:id`、`/api/skills/:id/import`），不能在那里放一个两段的动态路由。
- install.md 用 `text/markdown`，英文，只写站长审过的字段和由 Zip 算出的值；`?host=` 把那个宿主排第一。里面的 Zip 地址带 `?via=install`，助手照着装不重复记安装。
- 显示的版本：当前版本已发布就用它；当前版本被撤回或弃用而没指定新的，就用最新的已发布版本。
- 文件原文页 `/[locale]/resources/skills/[slug]/v/[version]/files/[...path]`：从存储读 Zip 解出单个文件，按 sha256 和路径缓存，图片和二进制只列名字，不进索引。已撤回版本的固定版本页按上面的规定保留内容（概述、文件），只是不能安装；以后如果有因为版权撤回的情况，再改成不显示文件原文。

**第 5 步的做法**：

- 收藏复用 `saves`（`src/modules/saves/target.ts` 的 `saveTypes` 加了 `skill`）。只有访客看得到的 Skill（已发布）能收藏：已下架的不显示收藏按钮，接口也拒绝；取消收藏总是可以。收藏状态在浏览器里读，页面照样静态生成。
- 桌面：收藏和分享两个按钮放在头部标签下面。画板上它们和作者卡在右上角，但右栏是安装面板，作者已经在头部的信息行里；「分享海报」本期不做（见上表），换成分享链接（有系统分享面板就用它，没有就复制页面地址）。收藏数跟在安装数后面（「· 1 人收藏」），没人收藏时不显示。
- 手机：分享是名字旁边的图标；底部固定一栏放收藏（只有书签图标）和「复制安装指令」，复制的是安装面板里选中的宿主的指令，和面板里的按钮共用状态，复制同样记一次安装。
- 「我的收藏」在应用后面加一段 Skill（只列已发布的），空状态多一个「逛逛 Skill」。
- 使用指南 `/[locale]/resources/guide` 没有画板，版式跟详情页：三步用上 Skill、各 AI 助手的 Skills 目录（只列安装面板里显示的宿主，目录、官网和安装说明都读后台「宿主」，安装说明按读者的语言，缺了用英文）、核对内容指纹（macOS / Linux 和 Windows 的命令）、安全检测查什么。列表「三步用上 Skill」下面的「查看使用指南」和详情页指纹下的「如何验证」（`#verify`）链过去。页面进搜索引擎，宿主改了随 `skills` 缓存一起刷新。
- 统计汇总：Inngest 任务 `skill-stats-rollup`（`src/modules/resources/stats/`）每小时第 7 分钟跑，也可发事件 `skill/stats-rollup` 立即跑。从 `skill_events` 数总安装数、近 7 天、前 7 天（往前 7–14 天，按跑的时刻往回数，不按自然日）的安装数，从 `saves` 数收藏，写进 `skills.stats`。只写数字变了的 Skill，用数据库适配器直接写（`payload.db.updateOne`，`updatedAt: null`）：不跑钩子、不进修改记录、不改更新时间，否则每小时会给每个 Skill 多一条修改记录。有变化才刷新 `skills` 缓存。
- 本周飙升（第 14 条）：近 7 天至少 20 次、而且比前 7 天多才算在涨，按增幅排；前 7 天是 0 的增幅算无穷大，排最前，显示「新上榜」，其余显示「+250%」这样的整数百分比。取前 3，不够 3 条整块不显示；和画板一样放在「三步用上 Skill」下面。「近期飙升」排序用同一个口径：在涨的 Skill 按增幅排前面，其余按近 7 天安装数。
- 安装榜：右栏热门标签上面，按总安装数取前 5，没人装过的不上榜；排名前 3 用强调色。「完整榜单」= 按安装数排序的列表。画板上叫「下载榜」，规格叫安装榜（复制指令也算），用规格的名字。右栏按画板改成不加框的几段，第 4 步给热门标签加的框去掉了。

## 后台

1. **录入**：在 `skills` 里新建（或从投稿队列「转为 Skill」），填来源仓库地址（可带子目录和 commit），点「导入版本」。后台任务拉取仓库快照，找到 `SKILL.md`，解析 frontmatter，打包 Zip，算 sha256 和文件清单，跑静态检测，用 AI 起草四种语言的说明和权限 / 依赖清单，生成一个「检测中 → 待审」的版本。
2. **审核**：你核对说明文字、分类、标签、许可、API Key、运行依赖，逐个宿主填兼容状态，看检测结果；通过的版本点「发布」，Skill 状态变为已发布。检测「拦截」的版本不能发布；「有提示」的看过发现以后可以发布，留一句备注。
3. **新版本**：上游有新 commit 时手动再点「导入版本」，写更新说明，发布后旧版本仍可访问。旧版本可以标「已弃用」或「已撤回」（填原因）。
4. **下架**：整个 Skill 下架要填原因，主页显示原因。
5. **投稿队列**：`skill_submissions` 按状态列出，处理后给提交人发邮件（Resend）。
6. **宿主**：`agent_hosts` 里维护 6 个宿主的名字、logo、目录位置和安装说明。

## 定时任务与 AI

任务（Inngest，日报第 1 步接入之后复用）：

- `skill/import`：拉仓库、打包、清单、检测、起草说明。同一 commit 重复导入只生成一次。
- `skill/describe`：起草一个版本的说明（导入后 Skill 还没有说明时自动排队，也可在版本页手动重写）；每 20 分钟补漏一次还在等待的草稿。
- `skill/stats-rollup`：每小时汇总 `skill_events` 到 `skills` 的统计缓存，算近 7 天安装数和飙升。
- `skill/submission-notify`：投稿状态变化时发邮件。

模型用途只有一个，经 `src/lib/ai`：`skill.describe`，输入 SKILL.md、README 和文件清单（全部作为数据），输出四种语言的显示名、一句话介绍、「它能做什么」、使用示例、注意事项，以及提取出的外联域名、读写范围、需要的工具和 API Key。起草结果必须经你审核才发布；模型失败时字段留空由你手写，不阻塞导入。简体保存后自动生成繁体。

第 3 步的做法：草稿状态记在版本上（「说明草稿」：待生成 → 已生成 / 没生成）；首次导入自动起草只填空着的字段，之后在版本页点「生成说明草稿」重写；显示名只在空着时填，试用笔记不动；除上面列的字段外也起草「工作流程」；已发布版本的声明不改；名字、数字和声明都和文件核对，文件里没有的外联域名、工具、API Key 不写入，列在面板上请你看。README 取包内的，没有时取仓库根目录的。

**静态检测**用规则，不用模型。每个版本导入时跑一遍：

| 检查 | 命中后 |
|---|---|
| 包结构：有 `SKILL.md` 且 frontmatter 合法；路径不越界（`../`、绝对路径、符号链接）；文件 ≤ 200 个、解压 ≤ 10 MB、单文件 ≤ 2 MB；只允许文本类文件和常见图片，不允许可执行二进制 | 拦截 |
| 密钥：常见的 AWS、GitHub、OpenAI、Anthropic 等 key 模式和私钥块 | 拦截 |
| 读取敏感位置：`~/.ssh`、`~/.aws`、钥匙串、浏览器资料、shell 配置文件 | 拦截 |
| 危险命令：`rm -rf`、`curl … \| sh`、`sudo`、`base64 -d` 后执行、eval 混淆 | 有提示 |
| 外联：提取所有 URL 和域名，和 SKILL.md 里声明的对比，列出未声明的 | 有提示 |
| 提示注入迹象：要求忽略规则、隐藏操作、不要告诉用户 | 有提示 |
| 许可：仓库有可识别的 LICENSE（SPDX），或者作者书面同意 | 没有则不能发布 |

结果三种：**通过**、**有提示**（你复核后可以发布）、**拦截**（不能发布）。前台只显示通过的检查项和「这个版本暂不可安装」；具体文件和行号只在后台和给投稿人的邮件里。拦截时如果已有通过的旧版本，旧版本继续可装。

## 多语言

- 界面文案、分类名在 `messages/`；宿主的安装说明在 Payload 里 localized。
- 显示名、介绍、说明、更新说明：AI 起草简体、英语、日语、韩语 → 你审核 → 繁体由简体用 OpenCC 生成。审核过的文字不加「机器翻译」标记（和日报一致）。
- 不翻译：slug、SKILL.md 正文、文件内容、目录路径。SKILL.md 原文外层带作者语言的 `lang`。
- 安装指令的句子跟界面语言；里面的地址和路径不变。
- 作者名、许可、宿主名不翻译。

## 实现顺序

每一步一个 PR，合并前在预览环境检查。第 2、3 步依赖日报第 1 步的 Inngest 和 `src/lib/ai`，所以资源在日报之后开工。

1. **数据与后台**：五个 Payload 集合、`skill_events` 表和迁移（收藏复用应用模块的 `saves` 表）；宿主与分类的初始数据；后台能手动录入一个 Skill。
2. **导入与检测**：GitHub 导入任务，Zip、清单、sha256、R2 存储，静态检测和结果展示，发布 / 撤回 / 下架和不可改校验。
3. **说明起草**：`skill.describe`，审核流程，繁体生成。
4. **前台**：列表、详情（桌面、手机）、固定版本页、`install.md` 和下载接口、安装事件、首页接真实数据。
5. **收尾**：使用指南、发布指南与投稿表单、收藏、统计汇总（安装榜、本周飙升）、空状态和加载状态。

## 验收标准
